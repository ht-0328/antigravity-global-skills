# 成果物の選択基準

ユーザーの目的からAntigravityの成果物種別を判定するための基準。ユーザーに種類を選ばせず、Agentが判定する。

## 決定表

| 条件 | Skill | Custom Subagent | Rule | Workflow |
|------|:-----:|:---------------:|:----:|:--------:|
| 特定タスクの知識・手順・規約を追加する | ✓ | | | |
| 独立した会話コンテキストが必要 | | ✓ | | |
| 並列実行や長時間の調査が必要 | | ✓ | | |
| 限定ツール・専用モデル・専用実行ポリシーが必要 | | ✓ | | |
| 親Agentから委譲される独立した役割がある | | ✓ | | |
| Agentの振る舞いを常時制御する | | | ✓ | |
| 条件付きのスタイル・制約を適用する | | | ✓ | |
| 繰り返し可能な手順をスラッシュコマンドで呼び出す | | | | ✓ |
| 固定された処理順序が中心 | | | | ✓ |

MCP設定と補助スクリプトは、上記の成果物と組み合わせて使う。

| 条件 | 成果物 |
|------|--------|
| 外部システム・API・データソースへの接続能力が必要 | MCP設定 |
| 決定的な変換・検査・反復処理をコードで実行する | 補助スクリプト（Skill内の`scripts/`） |

## 各成果物の詳細

### Skill

- **製品上の役割**: 現在のAgentへ特定タスクの知識、手順、規約、テンプレート、スクリプト利用方法を必要時に追加する。
- **読み込み方法**: 起動時に`name`と`description`のみ読まれる（Discovery）。依頼内容が`description`に合致すると`SKILL.md`全体が読み込まれる（Activation）。実行中に`references/`や`scripts/`を必要時に参照する（Execution）。
- **コンテキスト**: 親Agentのコンテキスト内で動作する。独立した会話コンテキストを持たない。
- **配置場所**: `authoring-formats.md`を参照。
- **適する用途**: コードレビュー手順、ドキュメント生成規約、テスト戦略、テンプレート生成、特定フレームワークのベストプラクティス
- **適さない用途**: 長時間の独立調査、並列実行が必要な処理、Agentの常時制約
- **組み合わせ例**: `scripts/`に補助スクリプトを含む、Custom Subagentの`skills`フィールドで参照される

### Custom Subagent

- **製品上の役割**: 親Agentから委譲される独立した役割を、分離されたコンテキストで実行する。
- **呼び出し方法**: 親Agentが`invoke_subagent`ツールで呼び出す、またはユーザーが明示的に呼び出す（詳細は`authoring-formats.md`参照）。
- **コンテキスト**: 独立した会話コンテキストを持つ。親Agentのコンテキストとは分離される。
- **配置場所**: `authoring-formats.md`を参照。
- **適する用途**: 大規模リポジトリの並列調査、セキュリティ監査、専門的なコードレビュー、長時間の非同期タスク
- **適さない用途**: 単純な手順の実行、親Agentのコンテキストが必要な処理
- **組み合わせ例**: `skills`フィールドでSkillを参照する、`tools`フィールドで必要なツールだけを指定する

### Rule

- **製品上の役割**: Agentの振る舞いを常時または条件付きで制御する制約、スタイル、プロジェクト固有のルール。タスク手順ではなく行動規範。
- **読み込み方法**: セッション開始時に自動読み込み。
- **コンテキスト**: 常にAgentのコンテキストに存在する。
- **配置場所**: `authoring-formats.md`を参照。
- **適する用途**: コーディングスタイルの強制、コミット前テストの必須化、使用言語の指定、禁止操作の定義
- **適さない用途**: 特定タスクの詳細手順、複雑な分岐ロジック
- **組み合わせ例**: SkillやSubagentの共通制約を定義する

### Workflow

- **製品上の役割**: ユーザーが明示的に呼び出す、繰り返し可能な一連の手順。スラッシュコマンドとして実行される。
- **呼び出し方法**: ユーザーがチャットでスラッシュコマンド名を入力して実行。
- **コンテキスト**: 親Agentのコンテキスト内で動作する。
- **配置場所とファイル形式**: `authoring-formats.md`を参照。
- **適する用途**: デプロイ手順、リリースチェックリスト、定型的なPR作成手順
- **適さない用途**: 常時適用する制約（→ Rule）、タスク知識の蓄積（→ Skill）
- **組み合わせ例**: Skillの知識を利用して一連の処理を進める

### MCP設定

- **製品上の役割**: 外部システム、API、データソース、実行機能への接続能力を提供する。
- **設定方法**: `authoring-formats.md`を参照。
- **適する用途**: データベース接続、外部API呼び出し、専用ツール連携
- **備考**: MCP自体は接続能力であり、その能力を活用する手順はSkillやWorkflowで定義する。

### 補助スクリプト

- **製品上の役割**: 決定的な変換、検査、反復処理をコードで確実に実行する。
- **配置場所**: Skill内の`scripts/`ディレクトリ。
- **適する用途**: ファイル変換、lint実行、テンプレート展開、データ検証
- **備考**: Skillの一部として配置する。単独で成果物にはならない。

## 判定の補助質問

判定に迷う場合、次の質問を自分自身に問いかける。

1. この機能は、現在のAgentの会話の中で完結するか？ → Yes: Skill、No: Custom Subagent
2. この機能は、すべての作業に常に適用されるか？ → Yes: Rule、No: Skill/Workflow
3. この機能は、ユーザーが明示的にコマンドで呼び出すか？ → Yes: Workflow、No: Skill
4. この機能は、外部システムとの接続が必要か？ → Yes: MCP設定を含む
5. この機能は、コードで確実に実行した方がよい処理があるか？ → Yes: 補助スクリプトを含む

## 根拠の種別

| 項目 | 根拠種別 |
|------|----------|
| Skillの配置場所・frontmatter | Antigravity公式仕様 |
| Custom Subagentの配置場所・frontmatter | Antigravity公式仕様 |
| Ruleの配置場所（AGENTS.md） | Antigravity公式仕様 / Agent Skills標準 |
| Workflowの配置場所・形式 | Antigravity公式仕様 |
| MCP設定 | Antigravity公式仕様 / MCP 2026-07-28仕様 |
| Progressive disclosure（3段階読み込み） | Agent Skills標準 |
| 各成果物の適する/適さない用途 | このリポジトリの設計方針 |
| 判定の補助質問 | このリポジトリの設計方針 |
